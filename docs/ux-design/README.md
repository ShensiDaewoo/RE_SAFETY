## 기획서 문구

**짧은 버전 (3문장)**

> Pleos Connect는 운전 안전을 위해 주행 화면(Driving View)을 시스템 고정 영역으로 두고 있어, 일반 앱은 그 자리를 바꿀 수 없습니다. RE:SAFETY는 이 규칙을 지키면서 앱 영역에서 실제 Pleos SDK로 차량 상태 조회·보호 모드·위치·내비 전환·음성 안내를 구현했고, 동시에 차량 화면 전체를 쓰는 Aurora HMI를 독립 시연본으로 완성했습니다. Pleos가 정차와 사고 상황에 한해 사용자 정의 화면을 허용하는 HMI 확장 인터페이스를 연다면, 같은 APK에 들어 있는 Aurora 화면과 장면 전환 로직을 연결해 차량 화면 전체에서 한층 몰입감 있고 일관된 안전 경험으로 확장할 수 있습니다.

**긴 버전 (설명 단락)**

> RE:SAFETY의 목표 화면은 상황에 따라 화면의 주인이 바뀌는 차량 HMI입니다. 정차 중에는 푸른 Aurora 화면이 출발 전 점검과 좌석·안전벨트 확인을 돕고, 주행 중에는 Pleos 기본 주행 화면과 내비게이션이 운전에 집중하게 하며, 사고 뒤 안전하게 정차하면 붉은 Aurora 화면이 119·SOS·보호 모드·사고 정리를 한 화면에서 안내합니다.
>
> 현재 공개된 Pleos 개발 환경에서 앱은 주행 화면 영역을 가리거나 바꿀 수 없습니다. 그래서 RE:SAFETY는 플랫폼 규칙을 우회하지 않고 두 가지로 증명했습니다. 첫째, Pleos 에뮬레이터의 앱 영역에서 실제 Pleos SDK가 동작합니다. 보호 모드 요청이 가상 차량의 문 잠금과 조명을 실제로 바꾸고, 주행이 시작되면 Pleos 내비로 화면을 넘깁니다. 둘째, 같은 APK가 일반 Android 전체 화면에서 Aurora 디자인과 세 장면 전환을 그대로 보여 줍니다.
>
> 주최사와 OEM이 정차·사고 상황에 한한 HMI 확장 권한을 제공한다면, RE:SAFETY는 이미 갖춘 화면과 판단 로직을 차량 화면 전체로 옮겨, 주행 정보는 그대로 지키면서 사고 직후 운전자에게 필요한 정보를 가장 크고 분명하게 보여 주는 통합 안전 HMI로 발전할 수 있습니다.

쓸 때 지킬 것: "OEM 통합 완료"가 아니라 "OEM 통합 목표"입니다. 3·4번 그림은 실행 화면이 아니라 합성 그림이라고 함께 적습니다.

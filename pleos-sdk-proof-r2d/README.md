# RE:SAFETY (리세이프티)

**사고 직후 정차한 차 안에서, 119·112 전화 화면과 현재 위치 확인, 사고 상황 정리와 구조 인계(QR)까지 돕는 Pleos Connect 앱입니다.**

차량 신호로 탑승자나 부상을 단정하지 않습니다. 자동 사고 감지, 자동 신고, 자동 위치 전송은 하지 않습니다. 119·112는 전화 화면만 열고 통화는 사용자가 직접 겁니다.

- 앱 이름: RE:SAFETY (리세이프티)
- 패키지: `com.contest.signalprobe.r2d`, 버전 0.8.0-r2d-dev (versionCode 24)
- 언어/도구: Kotlin, Gradle (Android Gradle Plugin 8.8.2), minSdk 28, targetSdk 34, compileSdk 35

## 1. 주요 기능
| 기능 | 설명 |
|---|---|
| 119 전화 연결 | 홈 왼쪽 큰 배너. 119가 입력된 전화 화면을 엽니다 |
| SOS | 홈 오른쪽 큰 배너. 119·112 전화 화면, 전화로 말할 현재 위치 확인, 사고 기록을 한곳에 모은 안내 화면입니다. 네트워크 전송은 없습니다 |
| 112 | 사이드바 아래 파란 원형 버튼. 112가 입력된 전화 화면을 엽니다 |
| 좌석·안전벨트 | 차량이 보고한 좌석 상태와 사람이 직접 확인한 결과를 두 열로 분리해 표시 |
| 보호 모드 | 정차(기어 P, 속도 0)에서 사용자가 누를 때만 미등·후방 안개등·실내등 켜기, 문 잠금 풀기. 요청 뒤 값을 다시 읽어 확인하고 되돌리기 지원 |
| 사고 상황 정리 6단계 | 행동 확인 → 부상 입력 → 차량 상태 → 공유할 내용 → QR → 완료 |
| 사고 기록 | 위치·차량 관측·직접 확인·사용자 입력·미확인을 출처별로 저장, 앱 재시작 후 복원 |
| QR 공유 | 인터넷 없이 휴대폰 카메라로 읽는 QR(현장 도움 / 보험·사고 정리 / 개인 보관). 포함 항목은 사용자가 선택 |
| 출발 전 확인, 보험·견인 | 좌석별 동승 메모, 보험사 번호, 견인 통화용 위치·첫마디 |

## 2. 사용한 Pleos SDK (공식 Maven `nexus-playground.pleos.ai`)
- `ai.pleos.playground:Vehicle:2.3.2` — 기어·속도·좌석·문·와이퍼·하향등·배터리 조회, 조명·문 잠금 제어
- `ai.pleos.playground:FusedLocation:1.1.3` — 차량 좌표
- `ai.pleos.playground:NaviHelper:3.0.5` — 현재 위치 주소(경로 요청 없음)
- 그 외: ZXing core 3.5.3(QR, Apache-2.0, 서버 불필요)
- 선언 권한 13개(병합 매니페스트에는 SDK 바인딩 권한 2개가 더해져 15개). **INTERNET·CALL_PHONE 권한 없음**.

## 4. 실행 방법
1. Pleos Connect 에뮬레이터를 실행합니다(위 환경).
2. APK 설치: `adb install -r apk/<APK 파일명>`
3. 런처에서 **RE:SAFETY**를 엽니다. 첫 실행 때 위치·속도 권한 요청이 나옵니다. 거부해도 앱은 동작하며 위치는 직접 입력하거나 전화로 말할 수 있습니다.
4. 정차 상태(기어 P, 속도 0)에서 모든 기능을 사용할 수 있습니다.
5. **이 개발 에뮬레이터에서는 기어가 P가 아니면 Pleos 시스템이 앱 화면을 "주행 중에는 사용할 수 없습니다"로 가립니다**(앱이 아니라 플랫폼 동작으로 관측했습니다). 앱 자체에도 이동 중 잠금(보호 모드·좌석 확인·사고 상황 정리·출발 전 확인)이 있습니다.

## 5. 소스에서 빌드
```
gradlew.bat assembleSubmissionRelease -Pandroid.overridePathCheck=true
```
- 처음 한 번은 인터넷이 필요합니다(의존성 내려받기).
- `local.properties`에 `sdk.dir=<Android SDK 경로>`를 직접 만들어 주세요(압축 파일에는 포함하지 않았습니다).
- 결과: `app/build/outputs/apk/submission/release/app-submission-release.apk`. release 빌드는 **debug 키로 서명**되어 있습니다(별도 키 설정 없이 설치되도록 한 설정이며, 정식 배포 서명이 아닙니다).
- 빌드 파일에는 `submission`과 `lab` 두 변형이 선언돼 있습니다. **이 압축 파일에는 제출용 `submission` 변형의 소스만 들어 있습니다.** `lab` 변형(시험 서버를 쓰는 주변 SOS 실험, 사고 화면 시뮬레이션)의 소스는 제출 범위가 아니라서 넣지 않았고, 그래서 `lab` 변형은 이 압축 파일만으로는 빌드되지 않습니다. 제출 APK에는 lab 코드가 포함되지 않습니다.

## 6. 테스트
- 계측 테스트 31개(기존 26 + 홈 긴급 배치·SOS 화면·위치 화면·전화 인텐트·이동 중 홈 5개): `gradlew.bat assembleSubmissionReleaseAndroidTest` 후 에뮬레이터에서 `adb shell am instrument -w com.contest.signalprobe.r2d.test/com.contest.signalprobe.CaseCInstrumentation`
- 에뮬레이터에서 화면 이동, 기록 복원, QR 생성, 긴급전화 화면 열기(통화 0건)를 확인했습니다.
- QR 반복 시험: 새로 만든 Pleos 에뮬레이터(앱 데이터 없음, 권한 두 개를 실제 팝업에서 허용, 기어 P)에서 실제 화면 탭으로 두 경로(보험·견인 → QR로 공유 / 사고 상황 정리 → QR 만들기)를 20번씩 반복했고, 화면을 캡처해 OpenCV QR 디코더로 읽었습니다. **40번 중 40번** [RE:SAFETY]로 시작하는 내용이 읽혔고 앱 재실행·충돌은 0건이었습니다. 실제 휴대폰 카메라로는 확인하지 못했습니다.
- 같은 새 에뮬레이터에서 첫 설치·첫 실행(권한 팝업 2개), 현재 위치 화면(권한 허용 뒤 좌표 표시), 119·112 전화 화면 진입(통화 0건, ACTION_CALL 0건)을 확인했습니다.

## 8. 알려진 한계
- 에뮬레이터에서만 검증했습니다. 실차 동작, 문 열림·센서 변화·배터리 낮음·보호 모드 권한 거부 상태는 재현하지 못했습니다.
- 기어가 P가 아닐 때의 앱 사용은 이 에뮬레이터에서 시스템이 막습니다. 이동 중 화면 구성은 계측 테스트의 합성 입력으로만 확인했습니다.
- 사고 자동 감지, 앱 자동 실행, 주변 이용자 알림, 공공기관 전송은 이 앱에 없습니다.
- 음성 읽기(TTS)는 에뮬레이터에 엔진이 없어 동작하지 않았습니다.
